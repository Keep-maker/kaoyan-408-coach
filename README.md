# 408 考研智能学习助手

> 面向计算机考研 408 的 AI 学习督导：**能对话 → 会调工具 → 真改数据** 的智能体 + 打卡 / 动态追踪 / 掌握度评估 / 学习建议 / 动态路线 / 热点推送
> 一套「会算、会排、会提醒、还能被你追问」的闭环，而不是又一个打卡表 App。

比赛：人工智能大模型智能体设计大赛 · 作品形式：学习助手
知识体系：4 门课 / 24 章 / **143 个知识点** / 362 学时（含考频权重、难度、前置依赖）
练习题库：**7387 道题**（四科公开题库，含选项、答案、详细解析与来源链接）

---

## 一、为什么需要它（痛点 → 对应功能）

考研 408 的难点不是「不知道学什么」，而是**不知道现在到底会多少、下一步该学什么、学了会不会忘**。

| 考生真实痛点 | 本助手的做法 |
|---|---|
| 学完就忘，学一章丢一章 | 贝叶斯知识追踪（BKT）+ 遗忘曲线，逐点算「现在还剩多少」 |
| 不知道分丢在哪 | 按「考频权重 × 掌握缺口」排序出最该补的点 |
| 计划永远完不成，越拖越焦虑 | 按实际速度、剩余天数**自动重排**，甚至切换路线档位 |
| 强度够但没方向 | 四科/章节三级评估 + 风险评估，明确说「先补科网网络层」 |
| 信息差（大纲、报名、调剂） | 研招网官方资讯 + 全网热搜关键词过滤推送 |
| 坚持不下来 | 连续打卡 + 状态联动（状态低时推「最小启动」而不是硬扛） |

## 二、智能体（AI 督导）

打开左侧导航的 ** AI 督导** 即可与它对话。它不是套壳聊天框，而是**一个会调用工具的 Agent**：理解你的意图 → 调用对应工具 → 用**你的真实数据**算出结果 → 落库并改变后续计划。

### 1. 11 个已注册工具

| 类别 | 工具 | 作用 |
|---|---|---|
| 读 | `query_progress` | 整体掌握度、四科分数、剩余天数、速度是否达标 |
| 读 | `query_weak` | 最薄弱知识点排行（按 权重 × 缺口） |
| 读 | `query_due` | 今天到期 / 已过期的复习清单 |
| 读 | `query_plan` | 今日学习计划 |
| 读 | `plan_route` | 未来若干天的动态路线 |
| 读 | `hot_news` | 考研热点与官方资讯 |
| 写 | `check_in` | 打卡：记录今日时长与身心状态，可写笔记 |
| 写 | `log_study` | 登记某知识点的学习 / 复习 / 测验记录 |
| 写 | `replan` | 重新生成今日计划（状态差、时间被压缩时） |
| 写 | `rest_directive` | 状态不佳时的「最小启动」方案（主动降低今日目标） |
| 写 | `quiz_me` | 抽背出题 → 判分 → 更新掌握度与复习间隔 |

### 2. 你说一句话，它真的动手改数据

- 「**我的进度怎么样**」→ 调 `query_progress`：掌握度、预估分、四科差距、最易丢分的科目，全部实时算出来。
- 「**抽背我几个知识点**」→ 调 `quiz_me`：从题库按 薄弱度 × 考频 出题；你直接打答案给它，它用**关键词命中率**判分（≥75% 全对 / ≥50% 半对 / ≥25% 部分），再按 BKT 更新掌握度、把复习时间提前。
- 「**我学不动了，今天只有 40 分钟**」→ 调 `replan` + `rest_directive`：把今日计划压缩到 40 分钟以内，只留 1–2 件最值得做的事，并给「开始比学多少更重要」的最小启动建议。
- 「**我学完了最小生成树，花了 40 分钟**」→ 调 `log_study`：写入记录、提升该点掌握度、重算后续路线。

对话里每个回答下方都会标出**本轮调用了哪些工具**（ 标签），便于答辩时当场验证「它到底调了什么」。

### 3. 架构：本地规则引擎为主，大模型为可选增强

```
用户发言
 ↓
lib/agent.js 意图理解：rankPoints 打分匹配知识点（精确 > 包含 > 主名 > 别名 > LCS > 分词）
 ↓
lib/agent-brain.js 对话编排：多轮上下文（待答题目 pending）、判分、状态机（新指令自动结束当前题）
 ↓
lib/agent-tools.js 工具执行：11 个工具直接读写 SQLite（掌握度 / 计划 / 记录）
 ↓
lib/agent-reply.js 回复生成：数字全部来自引擎实算，绝不由模型编造
```

分工：**数据类问题（进度/薄弱/抽背/计划）走本地工具，毫秒级、数字可追溯；开放域问题（如「KMP 与朴素匹配的区别」）交给大模型**，并带上该生的真实学习数据作为上下文。

设计取舍：**Agent 的判断与数据操作 100% 跑在本地**，因此断网、模型欠费、超时都不影响可用性；大模型只用于开放域问答与建议措辞。若大模型不可用，界面会**如实显示「AI 增强暂不可用」**并自动回退，而不是假装在线。

## 三、核心功能

1. **全量题库刷题**：7387 道 408 题，按科目 / 章节 / 题型 / 难度组卷；支持随机与顺序、答题卡、计时和公式图片渲染；首页展示最近练习可继续或复盘，并提供按当前掌握度的薄弱点快练。
2. **自动判分与自评**：单选、多选即时判分；填空、简答、综合题对照详细解析自评，并展示原站完整解析。
3. **错题与收藏**：错题自动归档并可重练，收藏夹随时回看；每次练习生成正确率、分科表现与错题报告，报告内可展开错题解析并只练本次错题。
4. **掌握度闭环**：练习结果按知识点回写 BKT 与遗忘曲线，同步更新学习记录、复习日期和打卡时长。
5. **打卡与追踪**：每日打卡、学习记录、连续天数、90 天热力图、近 14 天学习强度与四科进度。
6. **个性化规划**：143 个知识点逐点评估，按剩余时间与真实速度生成今日计划、未来 14 天路线与可执行学习建议。
7. **考研信息聚合**：研招网官方资讯与全网热搜中的考研 / 计算机相关话题，含缓存与离线兜底。

> 加分项：**可对话的智能体**。11 个工具、多轮抽背状态机、判分后即时改数据（详见第二章）。

## 四、快速开始

要求：**Node.js ≥ 22**（使用内置 `node:sqlite`，零第三方依赖，无需 npm install）

```bash
cd outputs/kaoyan-408
npm start # 启动服务，默认 http://127.0.0.1:4080
```

浏览器打开 `http://127.0.0.1:4080` 即可使用。第一次打开是空白账号，点右上角**「载入演示数据」**可一键生成一个「复习到中期的考生」画像（60 天学习历史、398 条记录、82% 打卡率）用于演示。

其他命令：

```bash
npm test # 引擎 + 刷题服务测试（74 项断言，用临时库，不动你的数据）
npm run seed # 服务运行中时生成演示数据
node scripts/seed-demo.js 45 # 自定义模拟天数
npm run sync:quiz # 全量同步 408 公开题库（约 2-3 分钟）
npm run sync:quiz -- --limit-per-subject=50 # 只同步每科前 50 题，便于快速验证
npm run sync:quiz:extra # 按「科目」口径补拉根分类口径漏掉的题
npm run fix:chapters # 回填缺失章节（按小节名反推）
```

题库同步是增量的：重复执行会更新变化题目，不会清空学习记录。运行中也可以在「题库刷题 → 同步题库」发起后台更新，页面会显示实时进度。`KY_AUTO_SYNC=0` 可关闭首次空库时的自动同步。

生产容器同样会在空库首次启动时自动拉取题库，进度可通过 `/api/quiz/sync` 查询。题库数据保存在 `kaoyan-data` 卷中，重建容器不会丢失。

环境变量：`PORT`（默认 4080）、`HOST`（默认 127.0.0.1）、`KY_DB`（数据库路径）、`KY_LLM_KEY` / `KY_LLM_MODEL` / `KY_LLM_BASE`（大模型接入）。

### 接入大模型（可选）

配置优先级：**环境变量 > `config/llm.json` > `~/.bailian/config.json`**。

推荐用项目内配置文件（已被 `.gitignore` 忽略，不会泄露密钥）：

```bash
cp config/llm.example.json config/llm.json # 然后填入你的 base_url / model / api_key
```

`config/llm.json`：

```json
{
 "base_url": "https://<你的端点>/compatible-mode/v1",
 "model": "deepseek-v4.1-flash",
 "api_key": "sk-xxxx",
 "timeout_ms": 120000
}
```

说明：

- 任何 **OpenAI 兼容端点**都可接入（百炼 DashScope、专属 MaaS 部署、DeepSeek、自建 vLLM 等）。
- 当前默认使用 **deepseek-v4.1-flash**（响应快、适合对话）；换成 qwen3.8-max-0902 等大推理模型时，记得把 `timeout_ms` 调到 180000 以上。
- `timeout_ms` 对**推理型模型**（先输出 reasoning 再给答案）建议调大，建议 ≥ 120000。
- 启动时服务会做一次**真实连通性探测**，界面据此如实显示「AI 增强已启用 / 暂不可用」，**不会假装在线**。
- 大模型不可用（欠费、断网、超时）时，智能体自动回退本地规则引擎，**全部功能照常可用**。

## 五、核心算法（答辩重点）

### 1. 掌握度模型：BKT × 遗忘曲线

- 每道题按贝叶斯更新：`P(掌握|答对) = P(答对|掌握)·P(掌握) / P(答对)`，参数 `slip=0.12`（会却答错）、`guess=0.25`（不会却蒙对）。
 意义：**答对不一定是真会，答错也不一定是不会**，避免「一次做对就判定掌握」。
- 记忆稳定度（天）随复习拉长、随答错衰减；掌握度按半衰期 `retention = 2^(-t/stability)` 自然衰减。
 意义：同一个知识点，「一个月前学过」和「昨天复习过」的评分不同。
- 复习日期由目标保持率（85%）反推，形成「到期 → 复习 → 稳定度变长 → 间隔变远」的正循环。

### 2. 评估：三级 + 风险 + 估分

- 三级：知识点 → 章节 → 科目，全部按**考频权重**加权（不是简单平均，避免低频点拉高分数）。
- 风险评估：`权重 × (1 − 掌握度)` 的加权占比，直接回答「哪一科最可能丢分」。
- 估分标定（经验曲线）：掌握度 30%≈68 分 / 50%≈95 分 / 85%≈135 分（408 满分 150）。

### 3. 动态路线规划

每天按优先级流水线排产：

```
① 复习（到期 + 即将到期，按 权重×缺口 排序）
 → 复习预算上限 = 每日时长 × reviewShare，避免复习吃光新内容
② 高频薄弱点专练（权重 ≥ 4 且掌握 < 60%）
③ 新知识点（前置依赖已满足 → 章节顺序 → 权重）
```

策略档位按「剩余天数 × 实际日均速度 vs 未消化学时」自动切换：

| 档位 | 触发条件 | 行为 |
|---|---|---|
| 稳扎稳打 | 时间 > 需求 1.6 倍 | 全部知识点吃透，重点补难点 |
| 标准推进 | 常规 | 按权重取舍，重难点优先 |
| 保分突击 | 时间 < 需求 0.8 倍 | 放弃权重 ≤2 低频点，只保高频 + 抗遗忘复习 |

计划未完成会自动重排，不做「越欠越多」的无效计划表。

### 4. 题库刷题与掌握度

题库同步采用「公开列表分页 + 逐题详情」：分类、选项、正确答案、详细解析、难度和来源链接都写入 SQLite。组卷可按四科、章节、题型、难度筛选；练习完成后按知识点把结果回写 BKT 掌握度和复习日期。源站少量题目的章节缺失或跨科错位会按小节点名与知识库做校正，无法可靠映射的题仍可练习，但不会误改其他科目的掌握度。

### 5. 学习建议引擎

本地规则引擎生成五类建议（进度 / 复习 / 薄弱 / 科目 / 目标），**全部结论都能追溯到数据**（哪几个知识点、差多少分钟、能提多少分）。配置大模型后叠加其表述能力，失败自动回退，保证离线可用。

## 六、技术架构

```
server.js 零依赖 HTTP 服务（约 20 个 REST 接口）
lib/db.js node:sqlite 数据层（users/checkins/logs/mastery/plan/hot_cache/advice_cache/agent_chat/agent_state）
lib/engine.js 核心引擎：BKT + 遗忘曲线 + 三级评估 + 动态路线 + 建议规则
lib/hot.js 热点聚合（研招网 + 60s 热搜 API + 关键词过滤 + 缓存 + 离线兜底）
lib/llm.js 大模型接入（任意 OpenAI 兼容端点，配置：env > config/llm.json；含真实健康探测与超时保护）
lib/agent.js 智能体·意图理解层（工具定义 + 知识点打分匹配）
lib/agent-brain.js 智能体·对话编排层（多轮上下文、抽背状态机、判分、工具派发）
lib/agent-tools.js 智能体·工具执行层（11 个工具，直接读写 SQLite）
lib/agent-reply.js 智能体·回复生成层（数字全部来自引擎实算）
lib/question-source.js 题库同步与字段映射（增量同步、进度回调）
lib/quiz-service.js 组卷 / 判分 / 错题收藏 / 报告 / 掌握度回写
data/syllabus.js 408 知识体系：143 个知识点，含权重/难度/学时/前置依赖
data/quizbank.js 题库：51 道 408 核心考点题（含参考答案与判分关键词）
public/ 前端单页（原生 HTML/CSS/JS，10 个页面，含题库刷题中心）
public/vendor/katex/ 本地公式渲染（离线可用）
scripts/ 测试、演示数据与题库同步脚本
```

设计取舍：**算法跑在本地，AI 只做增强**。掌握度、路线、建议不依赖网络与模型可用性，离线也能答辩；断网、模型欠费都不会让系统「不能用」。

## 七、演示脚本（答辩 3 分钟版）

**第一幕：智能体会调工具（1 分钟）**打开 ** AI 督导** 页，依次点快捷话术：

1. 「**我的进度怎么样**」→ 它调用 `query_progress`，当场算出掌握度 / 预估分 / 四科差距 / 最易丢分的科目（注意回答下方的 工具标签）。
2. 「**抽背我几个知识点**」→ 调 `quiz_me` 出题；**故意只答对一半**（例如答「O(nlogn)」）→ 调 `grade_answer` 判分：显示命中 / 漏掉的得分点、掌握度变化、下次复习日期被提前。
3. 追问「**最该补哪里**」→ 调 `query_weak`，刚答错的那个点已经进了薄弱清单第一条。

**第二幕：它会主动改计划（1 分钟）**

4. 「**我学不动了，今天只有 40 分钟**」→ 调 `replan` + `rest_directive`：今日计划从 10 项压到 1 项、只留最关键的复习点。
5. 切回 **学习驾驶舱**：掌握度、今日任务、风险值都变了 —— 说明对话**真的写进了数据库**，不是聊天记录。

**第三幕：数据底座（1 分钟）**

6. **掌握度评估**：最该补的 10 个点（权重 × 缺口排序）、四科风险对比。
7. **学习路线**：未来 14 天路线 + 策略档位自动切换（稳扎稳打 / 标准推进 / 保分突击）。
8. **考研热点**：研招网官方资讯 + 全网热搜筛选（含离线兜底）。

一句话总结：**别人做的是记录工具，我们做的是「能对话、会调工具、真改数据」的智能体 + 用概率模型算你忘没忘、用动态规划排你明天学什么的督导系统。**
